"스위치는 2계층, 라우터는 3계층." 자격증 책 첫 장에 나오는 문장이다. 그런데 **"그래서 실제로 뭐가 다른데?"** 라고 물으면 말문이 막히는 경우가 많다.

이 글은 그 차이를 **말이 아니라 실제 장비 동작으로** 보여준다. Cisco Packet Tracer로 라우터·스위치·PC를 직접 구성하고, `ping`·`traceroute`·`show ip route`·`show mac address-table`·`arp`를 떠서, L2와 L3가 **무엇을 보고, 어떻게 전달하며, 어디서 갈라지는지**를 캡처와 함께 확인한다. 아래 모든 출력은 **PT 9.0.1에서 직접 실행한 실제 결과**다.

> 계층 개념 자체가 낯설다면 [네트워크 기초 완전 정복](/posts/2026-11-12-network-basics/)의 OSI 7계층·MAC/IP 부분을 먼저 보고 오면 좋다.

## 한눈에 보는 핵심 차이

| 구분 | L2 (스위치) | L3 (라우터 / L3 스위치) |
| --- | --- | --- |
| 무엇을 보고 전달? | **MAC 주소** (2계층) | **IP 주소** (3계층) |
| 참조 테이블 | MAC 주소 테이블 | 라우팅 테이블 |
| 전달 범위 | **같은** 네트워크(서브넷) 안 | **다른** 네트워크(서브넷) 사이 |
| 브로드캐스트 | 전파함(같은 도메인) | **차단함**(도메인 분리) |
| TTL | 건드리지 않음 | **1씩 감소** |
| 주소 변화 | 바꾸지 않고 그대로 스위칭 | 홉마다 **출발/목적지 MAC 재작성** |
| 대표 기능 | VLAN, STP, 포트 보안 | 라우팅, NAT, ACL, Inter-VLAN |

이 표의 **모든 줄**을 아래에서 실제 출력으로 증명한다.

## 실습 환경

라우터 1대(R1)가 서로 다른 두 네트워크를 잇는, 가장 전형적인 구성을 만들었다.

![L2/L3 실습 토폴로지 — R1 라우터가 LAN A와 LAN B를 연결](/images/l2-l3-topology.png)

| 장치 | 역할 | 주소 |
| --- | --- | --- |
| **R1** (2911 라우터, L3) | 두 LAN을 라우팅 | g0/0 = 192.168.10.1 / g0/1 = 192.168.20.1 |
| **SW_A / SW_B** (2960, L2) | 각 LAN의 스위치 | (IP 없음 — L2 동작) |
| **PC_A1 / PC_A2** | LAN A 호스트 | 192.168.10.11 / .12 (GW .10.1) |
| **PC_B1** | LAN B 호스트 | 192.168.20.11 (GW .20.1) |

- **LAN A** = `192.168.10.0/24` (PC_A1, PC_A2가 SW_A에 연결)
- **LAN B** = `192.168.20.0/24` (PC_B1이 SW_B에 연결)

핵심 질문 두 가지로 L2와 L3를 가른다.
1. **같은 LAN 안**(PC_A1 → PC_A2)에서는 누가 전달하나? → **스위치(L2)**
2. **다른 LAN 사이**(PC_A1 → PC_B1)에서는 누가 전달하나? → **라우터(L3)**

## L2 통신 — 스위치는 MAC 주소로 전달한다

먼저 **같은 서브넷** 안, PC_A1 → PC_A2 통신이다. 둘 다 `192.168.10.0/24`이므로 라우터가 필요 없다. 오직 SW_A(L2 스위치)만 거친다.

```text
PC_A1> ping 192.168.10.12

Reply from 192.168.10.12: bytes=32 time<1ms TTL=128
Reply from 192.168.10.12: bytes=32 time<1ms TTL=128
Reply from 192.168.10.12: bytes=32 time<1ms TTL=128
Reply from 192.168.10.12: bytes=32 time<1ms TTL=128
    Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)
```

**`TTL=128`** 을 기억해 두자. 윈도우 호스트의 기본 TTL이 128인데, **그대로 128**이 돌아왔다. 즉 **중간에 라우터를 거치지 않았다**는 증거다. 스위치는 TTL을 건드리지 않는다.

그럼 SW_A는 어떻게 전달했을까? 스위치의 **MAC 주소 테이블**을 떠 보자.

```text
SW_A# show mac address-table   (MCP pt_read_mac_table)

VLAN 1 (default)
 MAC               Port                dynamic
 0001.96BE.96BA    FastEthernet0/1     ← PC_A1
 00D0.BCE7.3BE7    FastEthernet0/2     ← PC_A2
 000D.BD75.B301    GigabitEthernet0/1  ← R1 (업링크)
```

스위치는 **IP를 전혀 모른다.** 어느 포트에 어떤 **MAC**이 붙어 있는지만 학습해서, 들어온 프레임의 목적지 MAC을 보고 해당 포트로만 내보낸다. (목적지 MAC을 아직 모르면 전 포트로 **플러딩**하고, 응답을 보고 학습한다.) 이것이 L2의 전부다 — **"MAC 주소표를 보고, 같은 네트워크 안에서 프레임을 전달한다."**

> PT의 시뮬레이션 모드로 프레임을 추적하면 SW_A의 판단이 그대로 보인다: *"프레임 출발지 MAC이 테이블에 없음 → 새 항목 추가 / 목적지 MAC 조회 → 해당 포트로 전달."* 스위치의 사고 과정에 IP는 한 번도 등장하지 않는다.

## L3 통신 — 라우터는 IP 주소로 라우팅한다

이번엔 **다른 서브넷**, PC_A1(`192.168.10.11`) → PC_B1(`192.168.20.11`)이다. 출발지와 목적지의 네트워크가 다르다(`.10` ≠ `.20`). 스위치만으로는 절대 닿을 수 없고, **R1(라우터)** 이 두 네트워크를 이어줘야 한다.

```text
PC_A1> ping 192.168.20.11

Request timed out.                                   ← 첫 패킷
Reply from 192.168.20.11: bytes=32 time<1ms TTL=127
Reply from 192.168.20.11: bytes=32 time<1ms TTL=127
Reply from 192.168.20.11: bytes=32 time<1ms TTL=127
    Packets: Sent = 4, Received = 3, Lost = 1 (25% loss)
```

두 가지가 L2와 **결정적으로 다르다.**

**① TTL이 128 → `127`로 1 줄었다.** 라우터는 패킷을 다른 네트워크로 넘길 때마다 TTL을 1씩 깎는다(무한 루프 방지). TTL이 1 줄었다는 것은 **정확히 라우터 1대를 통과했다**는 물리적 증거다. L2(앞의 128)와 L3(지금 127)의 차이가 숫자 하나로 드러난다.

**② 첫 패킷이 timeout 됐다.** 손실이 아니라 **ARP 때문**이다. PC_A1은 목적지가 다른 네트워크임을 알면, 목적지(PC_B1)가 아니라 **게이트웨이(R1)의 MAC을 먼저 ARP로 찾는다.** 그 사이 첫 패킷이 버려지고, 두 번째부터 정상 응답한다. 이 "게이트웨이에게 맡긴다"가 L3 통신의 핵심인데, ARP 테이블을 보면 명확하다.

```text
PC_A1> arp -a   (MCP pt_read_arp)

  Internet Address   Physical Address
  192.168.10.1       000D.BD75.B301   ← 게이트웨이(R1)의 MAC
  192.168.10.12      00D0.BCE7.3BE7   ← PC_A2 (같은 LAN)
```

주목할 점: **PC_B1(192.168.20.11)의 MAC은 ARP 테이블에 없다.** PC_A1은 PC_B1의 MAC을 끝까지 모른다. 다른 네트워크의 호스트이기 때문이다. 대신 프레임의 목적지 MAC에 **게이트웨이 R1의 MAC**을 적어 보낸다. "목적지가 우리 동네 밖이면, 일단 관문(라우터)에게 넘긴다" — 이것이 L2에는 없는 L3의 사고방식이다.

그럼 R1은 그 패킷을 어디로 보낼지 어떻게 알까? 라우터의 **라우팅 테이블**이다.

```text
R1# show ip route

Gateway of last resort is not set

     192.168.10.0/24 is directly connected, GigabitEthernet0/0
     192.168.20.0/24 is directly connected, GigabitEthernet0/1
```

라우터는 **IP 네트워크 단위**로 "어느 네트워크는 어느 인터페이스로" 라는 지도를 갖는다. R1은 목적지 IP `192.168.20.11`이 `192.168.20.0/24`(g0/1에 직접 연결)에 속함을 보고 그쪽으로 라우팅한다. **스위치의 MAC 테이블과 라우터의 라우팅 테이블 — 이 두 표의 차이가 L2와 L3의 차이 그 자체다.**

`traceroute`로 경로를 보면 라우터가 **홉(hop)으로 드러난다.**

```text
PC_A1> tracert 192.168.20.11

  1   0 ms   0 ms   0 ms   192.168.10.1    ← 홉1: R1 (게이트웨이)
  2   0 ms   0 ms   0 ms   192.168.20.11   ← 홉2: PC_B1 (목적지)
```

같은 LAN 통신(L2)에서는 이런 홉이 **하나도** 없었다. 라우터를 거칠 때만 홉이 생긴다.

## 결정적 차이 3가지 (실측으로 정리)

| 질문 | L2 (스위치) | L3 (라우터) | 이 글의 증거 |
| --- | --- | --- | --- |
| **무엇을 보나?** | 목적지 MAC | 목적지 IP | MAC 테이블 vs `show ip route` |
| **TTL은?** | 그대로 | 1 감소 | TTL 128 → 127 |
| **목적지 MAC은?** | 최종 목적지 그대로 | **홉마다 재작성**(→ 게이트웨이) | PC_A1 ARP에 PC_B1 없음 |

여기에 하나 더: **브로드캐스트 도메인.** 스위치는 브로드캐스트를 모든 포트로 퍼뜨린다(한 도메인). 라우터는 **브로드캐스트를 다른 네트워크로 넘기지 않는다.** 그래서 라우터로 네트워크를 나누면 브로드캐스트 폭풍이 한쪽에 격리된다 — 네트워크를 "분할"한다고 할 때의 핵심이 이것이다.

## L2(스위치)에만 있는 기능

L2 장비의 역할은 "같은 네트워크 안에서 프레임을 똑똑하게 전달"하는 것이고, 그 주변 기능들이 모두 **MAC/포트/프레임 수준**에서 돈다.

- **MAC 주소 학습 & 포워딩 / 플러딩** — L2의 본질
- **VLAN** — 하나의 물리 스위치를 여러 **논리 네트워크(브로드캐스트 도메인)** 로 분할. 포트를 VLAN에 배정해 그룹을 나눈다.
- **STP / RSTP** — 스위치를 여러 대로 이중화하면 생기는 **루프를 차단**(L2에는 TTL이 없어 루프가 치명적이라 꼭 필요)
- **트렁크(802.1Q) / 액세스 포트** — 여러 VLAN을 한 링크로 실어 나르는 태깅
- **포트 보안(Port Security)** — 포트에 허용 MAC 수/주소를 제한해 비인가 장치 차단
- **전이중 / 포트별 충돌 도메인 분리** — 각 포트가 독립 회선(1편 기준 CSMA/CD가 사실상 불필요해진 이유)

핵심: 이 목록 어디에도 **IP·라우팅·서브넷**이라는 단어가 없다. 전부 2계층 안의 이야기다.

## L3(라우터/L3 스위치)에만 있는 기능

L3 장비의 역할은 "서로 다른 네트워크를 잇고, 최적 경로로 패킷을 보내는" 것이다. 그래서 **IP/경로/주소변환/필터링** 기능이 붙는다.

- **라우팅(정적/동적)** — 라우팅 테이블 기반 경로 결정. 동적으로는 **OSPF·EIGRP·RIP·BGP**
- **서로 다른 서브넷 연결 & 브로드캐스트 도메인 분리** — L3의 본질
- **TTL 감소** — 홉마다 1씩 깎아 무한 루프 방지(위에서 128→127로 확인)
- **Inter-VLAN 라우팅** — VLAN으로 나뉜 네트워크들 사이를 라우팅(router-on-a-stick, 또는 L3 스위치의 SVI)
- **NAT** — 사설 IP ↔ 공인 IP 변환(집 공유기가 하는 일)
- **ACL** — 출발지/목적지 **IP·포트 기반** 트래픽 허용/차단(3·4계층 필터링)
- **ARP를 통한 홉별 MAC 재작성** — 패킷은 유지하되 각 구간의 프레임 MAC을 다시 씀

핵심: 전부 **IP(3계층) 이상**을 다루는 기능이다. 스위치는 이것들을 하지 못한다(못 하는 게 정상이다 — 계층이 다르니까).

## 그럼 "L3 스위치"는 뭔가?

현실에선 경계가 섞인다. **L3 스위치**는 이름대로 **L2 스위치의 빠른 하드웨어 포워딩 + 라우팅 기능**을 한 장비에 담은 것이다. VLAN마다 가상 인터페이스(**SVI**)를 두어 VLAN 간 라우팅을 라우터 없이 처리한다. 반대로 요즘 라우터도 스위칭 모듈을 품는다.

그래도 **개념의 축은 그대로**다: "**MAC으로 같은 네트워크 안을 전달하면 L2 동작**, **IP로 네트워크 사이를 전달하면 L3 동작**." 장비 이름이 아니라 **그 순간 어느 계층의 정보로 판단하는가**가 L2/L3를 가른다.

## 정리

| | L2 | L3 |
| --- | --- | --- |
| 한 문장 | MAC으로 **같은 네트워크 안** 전달 | IP로 **네트워크 사이** 전달 |
| 테이블 | MAC 주소 테이블 | 라우팅 테이블 |
| 상징 기능 | VLAN · STP · 포트보안 | 라우팅 · NAT · ACL |
| 이 글의 증거 | TTL 128, 플러딩/학습 | TTL 127, 게이트웨이 ARP, traceroute 홉 |

- **같은 서브넷**이면 스위치(L2)가 MAC으로 끝낸다. TTL은 128 그대로, 라우터는 등장하지 않는다.
- **다른 서브넷**이면 호스트는 게이트웨이에게 맡기고(ARP는 게이트웨이 MAC), 라우터(L3)가 라우팅 테이블을 보고 넘긴다. TTL은 홉마다 줄고(127), traceroute에 라우터가 찍힌다.

스위치와 라우터의 차이는 외워야 할 암기가 아니라, **`ping` 한 번에 TTL이 128이냐 127이냐로 직접 보이는** 동작의 차이다. 다음에 네트워크가 안 될 때, "이건 같은 서브넷(L2) 문제인가, 서브넷을 넘는(L3) 문제인가?"를 먼저 물으면 절반은 해결된 셈이다.

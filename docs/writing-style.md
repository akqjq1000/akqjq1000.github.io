# 글쓰기 스타일 가이드 (de-slop)

이 블로그 글이 "AI가 대량 생산한 느낌"을 주지 않고, 사람이 직접 검증하며 쓴
기록으로 읽히게 하기 위한 기준. 모든 신규·수정 글에 적용한다.

## 원칙

1. **기술적 사실은 바꾸지 않는다.** 명령·출력·결과·수치는 실제 검증된 값 그대로 둔다.
   문장만 다듬고, 사실을 지어내거나 바꾸지 않는다.
2. **읽는 사람이 한 번에 이해**하도록 쓴다. 과장과 장식보다 정확함과 흐름.

## 하지 말 것 (slop 마커)

- **볼드 남발.** 한 문단에 굵은 글씨는 꼭 필요한 **한두 개**만. 모든 핵심어를 굵게 하면
  아무것도 강조되지 않는다.
- **엠대시(—) 남발.** 대부분 쉼표·마침표·괄호로 바꾼다. 한 글에 몇 번이면 충분.
- **드라마틱한 결론 인용구.** "그 한 비트가 36번 반복되자 전부 드러났다" 같은
  수사적 마무리 대신, 담백한 사실로 끝낸다.
- **방어적 메타 문구 반복.** "실제로 검증했다 / 지어내지 않았다"를 문단마다 반복하지
  않는다. 글 맨 끝 각주 한 줄로 충분하다.
- **평서체 "~이다"의 기계적 반복.** 문장 길이와 어미를 섞어 리듬을 만든다.
- **똑같은 템플릿.** 모든 글을 "개요→관찰→원리→방어→정리"로 찍어내지 않는다.
  글마다 그 주제에 맞는 흐름을 택한다.

## 할 것

- **도입 2~3문장**: 이 글에서 무엇을, 왜 보는지 자연스럽게. 템플릿 문구 금지.
- **문단은 하나의 생각**. 길면 쪼개고, 접속으로 흐름을 잇는다.
- **코드·표·캡처**는 설명을 대신할 때만. 넣었으면 그 앞뒤로 "무엇을 보라"를 한 줄.
- **방어/교훈**은 과장 없이. 실제로 어떻게 고치는지 코드/설정으로.
- **마무리**는 한두 문장으로 핵심만. 명언 흉내 금지.

## 워게임 풀이 글 공통 (교육·합법 목적 명시)

webhacking.kr·pwnable.kr 등은 **합법적인 보안 학습용 워게임**이다. 글 서두나 말미에
교육 목적임을 한 줄로 밝히고, 가능하면 **올바른 방어 방법**을 함께 적어 공격이 아닌
학습 자료로 읽히게 한다. (AdSense·검색 품질 양쪽에 유리)
